# k27 patches for native piano

k27 = the k27 tree: xnu-12377.121.6 + the baseline series 0001-0052 (XNU 27.0.1, first brought up under a hypervisor). These
patches on top make the same kernel boot natively on piano at EL1 (each inert unless its boot argument is set):

| Patch | What |
| --- | --- |
| 0053 | One kernel for the VM and the HLOS: the PSCI conduit comes from the ADT's `/psci` method; `XNU_VM_GUEST=0` (K27_VARIANT=native) only changes the fallback to SMC |
| 0054 | SM8750 MPIDRs: Affinity2 in the reset handler's and `ml_get_cpu_number`'s CPU lookups (prime cores 0x10000/0x10100) |
| 0055 | `pstore-console=<phys>`: the console mirrored into a RAM mailbox that survives a reset (11 copies, majority on read; `tooling/native/xnu-log.py`) |
| 0056 | `piano-reset-after=<s>`: PSCI reset after N seconds, the Gunyah watchdog (32 s bite) as the backstop |
| 0057 | `piano-reset-to=bootloader`: the PMIC SDAM restart reason (SPMI arbiter v7, SID 0 byte 0x48 = 2) set at boot, so every reset lands in ABL fastboot |
| 0058 | pstore-console header stored 11 times too ("DBGR": signature, then 11 {start, size} pairs; the reader takes their majority): one decayed bit of the single size word had cut the log's tail |
| 0059 | On `!BSD` (IOBSD matching not finished after 30 s), every busy IOService with its clients and their state goes to the console: who holds the root up |
| 0060 | `piano-rtc=1` (`piano-rtc-offset=N`): the calendar starts from the PMIC RTC (PMK8550 RTC_RW, SID 0 PPID 0x061, read through the SPMI observer channel) plus the offset, else the SDAM offset cell 0x72; read only, `PEGetUTCTimeOfDay` asks it when ArmDTPlatform answers 0 (`docs/drivers/rtc.md`). Adds `osfmk/arm64/piano_rtc.h` = `package/PianoPower/PmicRtc.h` |

| 0061 | `piano-cpuidle=N`: cpu_idle's WFI becomes a PSCI CPU_SUSPEND vote when the next timer leaves its min-residency (1 ret, 2 + cluster cl5, 3 + CPU subsystem ss3; OS-initiated mode for the domain states, last-man bookkeeping; ss3 only with the LLCC island slice reserved), exit-latency holds (`piano_cpuidle_latency_hold`), per-CPU counters (`machdep.piano_cpuidle`, a console summary every 60 s with the AOP's RPMh sleep counters), a PSCI/RSC/RPMh/LLCC probe (`piano-pm-probe=1`). Adds `osfmk/arm64/piano_pm.c`, `piano_pm.h` and `piano_pm_policy.h` = `tooling/k27/piano-pm/piano_pm_policy.h` (host-tested: `tooling/k27/test-piano-pm.sh`) (`docs/power.md` §2). PSCI VERSION/FEATURES (SMC32) are sign-extended since 2026-11-12 (NOT_SUPPORTED -1, not 4294967295; the index lines of 0062-0064 follow) |
| 0062 | `piano-sleep=1`: macOS's system sleep as suspend-to-idle: IOCPUSleepKernel parks the other CPUs in PSCI states, freezes them, and the boot CPU idles polling the wake sources (power key, cover, keyboard, USB-C, a timer); mach_absolute_time stops across it, the calendar is advanced; full wake with the reason claimed; the Gunyah watchdog across the whole path; the ADT's sleep-disabled overridden only with the argument; `piano-sleep-test` for unattended cycles (`docs/power.md` §3). `machdep.piano_sleep` is `CTLFLAG_KERN` since 2026-11-12 (kexts read it with `kernel_sysctlbyname`; the kernels built before answer them EPERM, `docs/policy.md` §2.4; 0063's context line follows) |
| 0063 | `piano-boot-guard=SECS`: the installed system's boot guarded. At EARLY_BOOT the restart reason bootloader and the Gunyah watchdog held (32 s bite), pinged every 10 s by a thread call that also checks every CPU still takes interrupts (a nop IPI each; one quiet for two ticks: PSCI reset); at SECS healthy when the exec of `piano-boot-guard-exec` (launchd) was seen: the reason back to normal, the pings go on, so a later hang restarts macOS; else a reset into ABL fastboot. Off with `piano-reset-after` (0056 keeps both); `piano-reset-to=bootloader` keeps the reason. The watchdog gets one owner (`piano_watchdog_hold/release/ping`; 0056, the guard and 0062 are holders, so 0062's wake window no longer turns it off under the guard). Tests `piano-boot-guard-ping=0`, `piano-boot-guard-test=hang-at=N`; `machdep.piano_boot_guard`. Adds `osfmk/arm64/piano_guard_policy.h` = `tooling/k27/piano-guard/piano_guard_policy.h` (host-tested: `tooling/k27/test-piano-guard.sh`) (`docs/boot-guard.md`) |
| 0064 | `piano-llcc-island-live=1`: ss3 (idle level 3, `piano-sleep-state=3`) decided on the LLCC ISLAND1 words (ATTR0 0x26841300, ATTR1 0x26841308, broadcast base, read only) read at each ss3 decision and each suspend's entry, not once at boot, so a slice PianoA830 programs later counts without `piano-llcc-island-ok=1`. `piano-sleep-cancel=1`: a driver cancels the suspend in progress from its kOff or PreSleep (`piano_s2idle_cancel`, or IOPMrootDomain's `"piano-sleep-cancel"` platform function with no link dependency; the window from `willNotifyPowerChildren` to the freeze): nothing is suspended, a normal wake with the reason `piano.cancelled`; `piano-sleep-cancel-test=N` for the test. Adds `osfmk/arm64/piano_s2idle_policy.h` = `tooling/k27/piano-pm/piano_s2idle_policy.h` (host-tested: `tooling/k27/test-piano-pm.sh`) (`docs/power.md` §3.6, §3.7) |
| 0065 | A failed contiguous kernel allocation gives its pages back ungobbled (no boot argument: a fix). `kmem_alloc_contig_guard()` takes the pages (`cpm_allocate()`, gobbled, counted as wired) before `kmem_find_space()`; when that fails (a full kmem range, or a size above `vm_map_kernel_max_simple_mappable_size()`, 2 GiB less a page) the error path freed them still gobbled: phantom wired pages (17:27, 8 GiB: active + inactive + free + wired 1.6 GiB above the RAM) and, once an IOPL wired one with `vm_object_iopl_wire_empty()`, the 13 GiB boot's `vm_resident.c:6226 Assertion failed: !mem->vmp_gobbled` (`vm_page_unwire` from `vm_page_do_delayed_work`). Now ungobbled with both counts fixed, and a size the map refuses is refused before the contiguous search (`docs/bringup-debugging.md` §6). Compile-checked with the native kernel's recipe for `vm_kern.o` |
| 0066 | `piano-boot-args`: the arguments beyond DarwinBoot's 1023 bytes in the ADT. Right after `SecureDTInit()` in `PE_init_platform(FALSE)` (before the tunables and any kext) the line's `piano-boot-args=NAME` selects `/chosen/piano-boot-args-NAME` (`=0` none; no selector `/chosen/piano-boot-args`), whose string goes after a copy of the line in a 4096-byte buffer next to `const_boot_args`; `PE_boot_args()` returns the copy, so every `PE_parse_boot_argn()` sees both. Inert without the property and the selector. One console line (`piano-boot-args: /chosen/NAME (P bytes): T bytes appended, boot-args M bytes (line L)`); `kern.bootargs` stays 1024 bytes, cut after the last whole argument; the stackshot keeps DarwinBoot's line. Adds `pexpert/arm/piano_bootargs_policy.h` = `tooling/k27/piano-bootargs/piano_bootargs_policy.h` (host-tested: `tooling/k27/test-piano-bootargs.sh`); the tools: `tooling/adt/boot_args.py` (`docs/bringup-debugging.md` §5.2). In the 27.3 line's kernel `kernel-k273-0066-s0001-native.macho` |
| 0067 | `cs-native4k-skip=1` (owner decision 2026-11-14; default 0) skips the native 4K code-signing pre-hash: a 16 KiB-page signature keeps its own checks (code directory, cdhash, trust cache) and is published without the 4 KiB table, and `cs_validate_hash` accepts its 4 KiB pages unhashed (NX for the page crossing codeLimit, as the hashed path), so those files' page contents are not checked against their signatures; one line `code-signature pre-hash skipped (cs-native4k-skip=1): N files, M MiB not hashed (P 4 KiB pages ...)` `cs-native4k-skip-report` seconds (120) after the first skip; it wins over the threads. `cs-native4k-threads=N`: the native 4K code-signing pre-hash (`cs_native4k_prepare`, `XNU_NATIVE_CS_HASH_CACHE`: on 4 KiB pages a 16 KiB-page signature is authenticated when it is added, the whole signed range read and SHA-256ed per 16 KiB block and again per 4 KiB page) in parallel and in large reads: the caller and N-1 kernel threads (1..16, at most the CPUs) claim chunks of `cs-native4k-read-kib` (default 1024) and read each with one `vn_rdwr` per buffer, verify every block and fill its 4 KiB slots; the first error stops everyone and is returned; nothing is published before every helper has finished without error (the one-thread pass's table and refusals). A helper without memory does not take part. Default (threads 1, no read size): the original loop. `cs-native4k-log=MiB`: a console line per signature of at least that size (`cs_native4k: NAME: K KiB (B blocks) in T ms, N threads, R KiB reads: ok 0; total ...`); counters `cs_native4k_prepare_count/_bytes/_ns`. Why: 27.3's dyld cache (87 LZBITMAP-compressed files, 6.9 GB of content) kept launchd in this loop ~37 s (`docs/boot-time.md` §9). Adds `bsd/kern/cs_native4k_policy.h` = `tooling/k27/cs-native4k/cs_native4k_policy.h` (the work split and the skip's accept rule; host-tested with real threads, ASan/UBSan and TSan: `tooling/k27/test-cs-native4k.sh`). Applied to the 27.3 tree's clone by `tooling/k273/prepare-k27-tree.sh` (patches past `K27_TREE_TOP`, 0066); kernel `kernel-k273-0067-s0001-native.macho` |
| 0068 | `piano-halt-trace=1` (default 0): `piano-halt: ...` console markers on the halt/restart path, to name what holds every restart into the 30 s `Halt/Restart Timed Out @IOPlatformExpert.cpp:884`: PEHaltRestart's entry and handlePlatformHaltRestart's return, each phase with its uptime, NVRAM sync, every priority client handler before and after, notifySystemShutdown's return, the halt/restart platform actions (count, each return, the end), the PM quiesce (quiescePowerTree's result, every quiesce-blocking IOPM request attached and retired with target and type, the request's retirement, the callback), the platform's haltRestart (class, `PE_halt_restart`, return), the PSCI SYSTEM_RESET/OFF call and its result if it returns; at the timeout `panicWithShutdownLog` (the phase that did not end) instead of the bare panic (`docs/halt.md`; `tooling/native/halt-trace-verdict.py`). Kernel `kernel-k273-0068-s0001-native.macho` |
| 0069 | `piano-psci-halt` (default **1**; `piano-psci-halt=0` off, the course before): ArmDTPlatform has no `haltRestart` and nothing sets `PE_halt_restart`, so every `PEHaltRestart(kPERestartCPU/kPEHaltCPU)` got -1 (PianoDwc3's reset then waited out the 30 s timer and panicked). At EARLY_BOOT, natively and only when unset, `PE_halt_restart` becomes PSCI `SYSTEM_RESET` for a restart and `SYSTEM_OFF` for a power-off, through `piano_psci_reset`'s conduit; the PMIC restart reason untouched; other types -1 as before. `machdep.piano_psci_halt` switches it at run time. The restart word: marked at `PEHaltRestart`'s entry and by `machdep.piano_restart_started=1` (PianoDwc3's reset writes it before its reason); once marked the boot guard's health decision does not write the restart reason (a `reset fastboot` at 170 s once lost its reason to the 180 s decision). Adds `osfmk/arm64/piano_halt_policy.h` = `tooling/k27/piano-halt/piano_halt_policy.h` (host-tested: `tooling/k27/test-piano-halt.sh`) (`docs/halt.md`, `docs/boot-guard.md` §3). Kernel `kernel-k273-0069-s0001-native.macho` |

Build: `K27_VARIANT=native "$PIANO_K27_TREE/build-k27-piano.sh"` in the k27 tree with these patches applied to its `out/k27/xnu`
(see `docs/bringup-debugging.md` §4).

Kernel levels: `tooling/k27/build-native-image.sh` and the kexts' import checks link against `kernel-k27-0059-native.macho` unless
`K27_KERNEL` names another, so the default build kernel stops at 0059; 0060-0065 are opt-in by kernel (`K27_KERNEL=<kernel-k27-00NN-native.macho>`)
and then each by its own boot argument (`docs/power.md` §6).
