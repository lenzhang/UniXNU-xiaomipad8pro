# Tablet results, 2026-11-11 evening (RAM boots unless noted)

Measured on the tablet with the USB console capture (`tooling/native/usb-console.py`) and the console mailbox. Driver pages keep
the details; this page is the short record of what was proven tonight and what is still open.

| Test | Result |
|---|---|
| PianoPower level 1 (no DSP), Mac's USB-C port | battery **+477 mA at 97 %**: the PMIC charges by itself from the Mac's port without the DSP; the system runs from USB (0 mA) once the packs are near full |
| PianoPower level 2, no writes (image G2) | the DSP starts from macOS; `msm/adsp/charger_pd` up; USB-C port notifications (owner 0x800c) and UCSI (0x800b, version 1.10) answer; input suspend 0x2019 = 0, AICL enable 0x2012 = 0; the firmware's bus current **397 mA** at 5.2 V (type CDP) with its input limit at the 100 mA request; battery **−1.6 to −1.7 A** at the login screen: the input is not zero, it is held near 400 mA while the system draws about 9 W. Next: the board configuration + an input limit write (image I) |
| PianoA830 GPU bring-up | S1..S10 in 1.0-2.6 s, 160 MHz, 47-56 °C in G2 and daily2; **one hang** at S1.7 (GPU_CC read) in an older build ("power1"), reset by the Gunyah watchdog: under investigation (`docs/forensics-2026-11-11.md` when it lands) |
| PianoTouch level 1 | **passed on the first run**: GENI SPI loopback, NT36532 identified, the BOE firmware downloaded with the hardware CRC, scanning, the unit's calibration loaded (BOE, no flip), frames with good checksums |
| PianoWifi level 1 | matched the design: WLAN_EN low, PCIe0 and its PHY powered off, two PMU rails disabled (owned by another EE: level 2 votes them through RPMh) |
| PianoDwc3 `reset fastboot` | works: the monitor restarts the tablet into ABL fastboot (the Mac can recover the tablet without buttons while the console runs) |
| daily profile as a RAM image (GPU + PianoPower level 1 + USB console + the Mac's keyboard/pointer) | passed: GPU up, display on, console up, battery 0 mA at 97 % on the cable |
| daily profile installed on the ESP | written and verified (NAS backup first, read back through the partition and LUN 0), but its **first boot did not bring up the USB console**; the tablet needs a button reset to be read out. Open: the previous ESP is kept for a rollback, the failed boot's log is read at the next fastboot appearance |
